## Timing limitation found during testing

Vertex responses varied considerably. Initial identity lookup completed in approximately 28 seconds; the two-action timesheet turn took approximately 114 seconds. An early multi-action manager request committed its writes but hit the initial three-minute limit before returning a summary. The UI reported incomplete execution instead of falsely claiming success.

The final revision increases the bounded agent budget to six minutes and the Cloud Run request timeout to seven minutes. A restored conversation from an earlier revision still experienced a model timeout during a task lookup; its action list showed only a successful read, and the task stayed TODO. After checking the database and starting a fresh conversation, the final revision completed the task correctly. Fresh final-revision employee, manager and admin requests all returned successful responses.

This does not establish a latency guarantee. If a turn is interrupted or times out, check current records before repeating a write. A completed duplicate turn returns its cached response rather than executing again. Use short requests for the CEO demonstration and start fresh conversations before the demo.

The QA timesheet and task are explicitly labeled demonstration data (the task title begins `Chat QA`). They remain available to inspect in the portal. New chat clears conversational context, not enterprise records.
